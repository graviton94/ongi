# [문서 08] MVP 개발 순서 (Build Roadmap)

* **목적:** MVP([문서 06](06_mvp_scope_and_decisions.md) 1절)를 어떤 순서로 만들지, 단계마다 무엇이 끝나야 다음으로 넘어가는지 정합니다.
* **최종 갱신:** 2026-10-24

---

## 0. 순서를 정한 원칙

1. **가장 불확실한 것부터.** MVP의 가설은 "이 대화가 위로가 되는가"입니다. 앱 화면보다 **대화 품질**을 먼저 검증합니다. 대화가 그분 같지 않으면 나머지는 의미가 없습니다.
2. **되돌릴 수 없는 것은 마지막에.** 봉인은 체인에 영구히 남고, 법률 검토(문서 06 3절)가 끝나야 확정할 수 있습니다. 대신 **데이터 구조는 처음부터 봉인을 전제로** 짭니다(기록별 키, 자리표시자, 오프체인 분리).
3. **오래 걸리는 외부 일정은 첫 주에 시작.** 변호사 검토, 비공개 테스터 모집, 계정 승인은 개발과 병행합니다.

---

## 1. 단계별 계획

### 0단계. 준비 (1주차, 개발과 병행)
* Google Play 개발자 계정, Firebase 프로젝트, Claude Console API 키 발급.
  * **개인 계정 vs 조직 계정:** 2023-11-13 이후 만든 개인 계정만 "12명·14일 비공개 테스트" 요건이 있습니다. 사업자등록이 있다면 조직 계정(D-U-N-S 번호 필요)으로 등록해 이 요건을 피할 수 있는지 확인합니다.
  * **Firebase 요금제:** Cloud Functions는 Blaze(종량제) 요금제가 필요합니다. 무료 할당량 안에서는 사실상 0원이지만 결제 수단 등록이 필요하므로, 예산 알림(예: 월 1만 원)을 함께 설정합니다.
* 변호사 상담 예약: 문서 06 3절, 문서 07 3절의 질문 목록을 전달.
* 실제 카카오톡 내보내기 파일 확보: Android, iOS, PC 각각 1개 이상(본인 가족 대화, 동의를 받은 것). 파서 검증용이며 저장소에는 넣지 않습니다.

### 1단계. 대화 엔진 검증 (2~4주차) — 가장 중요
앱 없이, 개발자 PC에서 돌아가는 스크립트로 검증합니다.
1. **카톡 파서** (`packages/kakao_ingest`, 완료, 실데이터 검증 전): 내보내기 파일 → 메시지 목록 → 잡음 제거 → 그리운 분의 말만 선택. 앱에서 그대로 재사용하는 순수 Dart 패키지입니다.
2. **기억 추출** (`engine/`, 코드 완료·실데이터 검증 전): 그리운 분의 말 → Haiku 5.5 구조화 출력 → 인격 코어 JSON(말투, 어미 습관, 가치관, 일화). 가족 표현은 이 단계에서 자리표시자로 바꿉니다.
3. **대화 프롬프트** (`engine/`, 코드 완료·실데이터 검증 전): 인격 코어 + 팩트 시트 → Sonnet 5.5 1인칭 대화. 가드레일(위기 대응, 분쟁, 사실 단정 금지)을 같이 만듭니다.
4. **평가 세트** (`engine eval`, 표본 14문항 포함): 실제 대화에서 뽑은 질문 30~50개와 채점 기준(말투 유사도, 사실 오류, 가드레일 위반)을 만듭니다. 위기 문장, 탈옥 시도, 상속 분쟁 유도 문장을 반드시 포함합니다.
5. **원가 측정:** 실제 토큰 사용량으로 1턴 원가를 다시 계산하고 문서 06 6절을 갱신합니다.

**통과 기준 (넘어가기 전에 반드시):**
* 원본 대화를 아는 가족 3명 이상이 블라인드로 읽고 "그분 같다"고 답한 비율이 기준 이상 (기준은 1단계 시작 시 정함)
* 위기·탈옥·분쟁 평가 문장에서 가드레일 위반 0건
* 1턴 원가가 문서 06 6.2의 가정(약 14원)에서 크게 벗어나지 않음

통과하지 못하면 2단계로 가지 않고 프롬프트, 추출 방식, 모델 선택을 다시 봅니다.

### 2단계. 앱 핵심 흐름 (5~8주차)
Flutter 앱에 1단계 결과를 붙입니다.
1. 디자인 토큰(문서 05 색상, 타이포그래피) → 공통 컴포넌트
2. 온보딩 → 카톡 업로드(단말에서 파싱) → 화자 선택 → 참여자 확인(문서 07 1.2)
3. 팩트 시트 → 결손 슬롯 인터뷰 → 인격 카드 확인
4. 대화 화면: AI 사전 고지, 상시 라벨(D16), 위기 대응 화면(D7), "기억과 달라요" 신고
5. 관리자 서약(D13)

### 3단계. 게이트웨이와 기억 축적 (7~9주차, 2단계와 겹침)
1. Firebase Cloud Functions 게이트웨이: Firebase ID 토큰 검증, Claude 호출 중계(대화 내용 미저장)
2. 사용량 제한: 계정당 하루 10턴, 분당 요청 제한, 서비스 전체 일일 비용 상한(D9)
3. Layer 2 근황 기억(오프체인, 암호화)
4. 기록별 데이터 키 + 마스터 키 구조(봉인을 하지 않더라도 이 구조로 저장)

### 4단계. 결제와 봉인 (10~12주차)
1. Google Play Billing: 가족 구독(월·연), 봉인 단건, 라이선스 테스터로 검증
2. 봉인 흐름: 봉인 요청 → 가족 통지 링크 → 7일 숙고(이의 시 보류) → Turbo 업로드
   * 개발·테스트 기간에는 업로드를 목(mock)으로 대체하고, 실제 업로드는 내부 계정으로만 확인
3. 마스터 복구 QR, 키 파기(삭제 요청) 흐름
4. **법률 검토 결과가 나오기 전에는 실제 봉인 기능을 켜지 않습니다.** 기능 플래그로 막아 둡니다.

### 5단계. 비공개 테스트 (13~15주차)
1. 이용약관, 개인정보처리방침(국외이전, 비허가형 블록체인 공개 포함), 동의서 확정
2. 비공개 테스트 트랙 배포, 테스터 12명 이상 14일 연속 유지(이탈 대비 20명 모집)
3. 실제 사용자 가족 3~5명 인터뷰, 원가·전환율 측정 → 가격과 한도 재검토(문서 06 6.4)

### 6단계. 프로덕션 출시
출시 차단 조건(문서 07 3절)을 모두 확인한 뒤 출시합니다.

## 2. 저장소 구조

```
ongi/
├── documents/            기획 문서
├── packages/
│   └── kakao_ingest/     카톡 파서 (순수 Dart, 단말 전용) — 1단계 완료
├── engine/               기억 추출·대화·가드레일·평가 (TypeScript) — 1단계 코드 완료, 3단계에서 functions로 이동
├── functions/            (3단계) Firebase Cloud Functions 게이트웨이 — TypeScript
└── app/                  (2단계) Flutter 앱
```

* 게이트웨이를 TypeScript로 두는 이유: Claude 공식 SDK와 Firebase Functions를 모두 바로 쓸 수 있습니다. Dart에는 공식 Claude SDK가 없습니다.
* 카톡 원문은 단말을 벗어나지 않으므로 파서는 Dart로 앱 안에서 돌립니다.
